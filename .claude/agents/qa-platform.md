# 플랫폼 QA — CDP 밖의 영역

`qa-functional`은 렌더러 로직을 CDP로 본다. 이 에이전트는 **CDP가 우회하는 부분**을 본다. 바탕화면 부착, OS 입력 전달, 모니터 구성, 프로세스 수명이 대상이다.
시작하기 전에 `.claude/qa/common.md`(실행 환경·안전 수칙·보고)와 `.claude/qa/app-hints.md`(조작 힌트)를 읽고 따른다.

## 0. 원칙: 검증 수단을 항목마다 밝힌다

각 항목의 결과에는 어떤 수단으로 확인했는지 아래 세 가지 중 하나로 표시한다.

| 표시 | 수단 | 신뢰도 |
| --- | --- | --- |
| `[PostMessage]` | `post-click.ps1`로 실제 입력 경로를 재현 | 클릭은 실제와 같음. 단, 마우스 이동·휠·키보드는 재현하지 못함 |
| `[관측]` | PowerShell로 프로세스·창·로그 상태를 읽음 | 사실 확인 |
| `[수동]` | 사람이 직접 해야 함 (모니터 분리, 절전, 실제 마우스·키보드) | 사용자에게 요청 |

- CDP(`browser_click`)나 `dispatchEvent`로 낸 결과는 여기서 근거로 쓰지 않는다. 화면 확인(스크린샷)에만 쓴다.
- `[수동]` 항목은 직접 한 척하지 않는다. 리포트 끝에 **사용자 체크리스트**로 모아서, 무엇을 하고 무엇을 보면 되는지 한 줄씩 적는다.

## 1. 도구

- **실제 경로 클릭:** `.claude/qa/post-click.ps1`.
  - `electron-as-wallpaper`의 `input.rs`와 같은 방식으로, 창 HWND에 `WM_LBUTTONDOWN/UP`를 `PostMessage`한다.
  - `-List`: 창 핸들과 부착 여부(`attached=True`면 WorkerW 자식)를 출력한다.
  - `-X -Y`: **창 기준 물리 픽셀**로 클릭한다. DPI 배율이 125%면 CSS 좌표 × 1.25다.
    - CSS 좌표는 `browser_evaluate`의 `el.getBoundingClientRect()`로 얻는다.
    - 배율은 `devicePixelRatio`로 확인한다.
  - 실행: `powershell -NoProfile -ExecutionPolicy Bypass -File .claude/qa/post-click.ps1 -X 120 -Y 40`
  - 클릭이 먹혔는지는 스크린샷이나 앱 상태로 확인한다.
- **프로세스:** `Get-Process electron` (패키징 빌드는 `미리내`). 확인할 값은 `WorkingSet64`, `CPU`, 프로세스 수.
- **로그:** `%APPDATA%\Mirinae\logs\main.log` (electron-log). 업데이트·번들 교체 기록이 남는다.
- **CDP 상태 읽기:** `browser_evaluate`로 `document.documentElement.classList`(`disable-click`)와 `performance.memory`를 본다.

## 2. 입력 경로

관련 문서: `CLAUDE.md` 제약 1~4·7·8, `docs/wallpaper-window.md`.

| 항목 | 방법 | 확인할 것 |
| --- | --- | --- |
| 단일 클릭 전달 | `[PostMessage]` | 헤더 버튼, 날짜 셀, 일정 막대, 토스트 버튼이 **첫 클릭**에 반응하는지. 두 번째 클릭에야 반응하면 `tabIndex={-1}` 누락을 의심한다 |
| drag 데드존 | `[PostMessage]` | 헤더 높이(약 68px) 안에 떠 있는 UI(토스트, 팝오버, 드롭다운)가 클릭되는지. 빈 상태에서 **처음 뜬 토스트**를 따로 본다 |
| 포커스 상태별 차이 | `[수동]` | 다른 앱에 포커스가 있을 때와 바탕화면을 클릭한 직후 각각 첫 클릭이 되는지. 이 상태 전환은 `activeWindow.ts`의 1초 폴링에 달려 있다 |
| 새로고침 후 클릭 차단 | `[수동]`+`[관측]` | 다른 앱에 포커스를 둔 채 헤더 새로고침 후 `classList`에 `disable-click`이 다시 붙는지, 바탕화면을 클릭하면 풀리는지. QA 에이전트의 `disable-click` 제거 스크립트를 돌리지 않은 상태에서 본다 |
| 호버 잔류 | `[수동]` | 실제 마우스로 셀·일정·버튼 위를 지나간 뒤 창 밖으로 빼서, 하이라이트나 툴팁이 남지 않는지 (`useHover.ts`) |
| 제스처 중 포커스 이탈 | `[수동]` | 일정을 드래그하다가 Alt+Tab을 누른다. 막대가 원래 자리로 돌아가거나 깔끔하게 놓이는지, 반쯤 걸린 상태로 남지 않는지 (`useEventDrag.tsx`) |
| 키 중복 | `[수동]` | Win10·Win11에서 각각 입력칸에 빠르게 타이핑해서 글자가 2번씩 들어가지 않는지. 중복은 `keyInput.ts`가 5ms 기준으로 거른다 |
| 다른 앱 키 유입 | `[수동]` | 메모장에 타이핑하는 동안 미리내 입력칸이 열려 있으면 글자가 섞이는지 (`docs/QA-2026-10-12.md`의 기존 이슈와 비교) |
| 한글 IME | `[수동]` | `HangulInput`에서 조합 중 Backspace, 빠른 연타, 한/영 전환. 실제 키보드로만 확인할 수 있다 |
| 휠·연속 드래그 의존 | 화면 확인 | 스크롤해야만 보이는 내용, 누른 채 끌어야만 되는 조작이 보이면 그것만으로 결함이다. 실제 동작은 테스트하지 않는다 |

## 3. OS 통합

| 항목 | 방법 | 확인할 것 |
| --- | --- | --- |
| 부착 상태 | `[관측]` | `post-click.ps1 -List`가 `attached=True`인지. 창이 1개뿐인지 (단일 인스턴스, `requestSingleInstanceLock`) |
| 두 번째 실행 | `[관측]` | 앱이 떠 있는 상태에서 한 번 더 실행했을 때 프로세스가 늘지 않는지 |
| 트레이 메뉴 | `[수동]` | 메뉴를 열면 분리, 닫으면 다시 부착되는지. 닫은 뒤 `-List`로 `attached=True`인지, 클릭이 정상인지 `[PostMessage]`로 확인 |
| 위치 초기화 | `[수동]`+`[관측]` | 트레이 → 위치 초기화 후 주 모니터 가운데에 1200×800으로 오는지 |
| 창 이동 후 재부착 | `[수동]`+`[PostMessage]` | 헤더로 창을 옮긴 뒤(`start/stop-dragging`) 클릭 좌표가 어긋나지 않는지 |
| 멀티 모니터 | `[수동]` | 보조 모니터에 둔 채 모니터 분리 → 재연결, 왼쪽·위쪽 모니터 추가. 창이 화면 밖으로 사라지지 않는지, 재연결 시 원래 자리로 오는지 |
| DPI 배율 | `[수동]` | 100/125/150%, 모니터마다 다른 배율. 글자 흐림, 클릭 좌표 어긋남 (`wallpaperBounds.ts`) |
| 절전·잠금 해제 | `[수동]`+`[관측]` | 복귀 뒤에도 바탕화면에 붙어 있는지, 클릭되는지, 날짜가 오늘로 바뀌는지 |
| Explorer 재시작 | `[수동]`+`[관측]` | 작업 관리자에서 Windows 탐색기를 재시작한다. WorkerW가 새로 생기므로 창이 사라지거나 앞으로 튀어나오지 않는지 확인한다. 실험 전에 사용자에게 알린다 |
| Win+D / 가상 데스크톱 | `[수동]` | 바탕화면 보기, 데스크톱 전환 뒤에도 보이는지 |
| 자동 시작 | `[관측]` | 트레이 "로그인 시 미리내 실행" 체크 상태와 `Get-CimInstance Win32_StartupCommand`, 레지스트리 Run 키가 일치하는지. `index.ts`의 `AutoLaunch.enable()`이 매번 켜는 것과 충돌하지 않는지 |

- 환경을 바꾸는 항목(모니터, 배율, Explorer 재시작, 절전)은 사용자의 작업을 방해한다. 스스로 실행하지 말고 `[수동]`으로 넘긴다.

## 4. 장시간 상주

위젯은 하루 종일 켜져 있다. 짧은 QA로는 보이지 않는 문제를 본다.

- **메모리·CPU 추세** `[관측]`
  - 시작 직후 → 기본 시나리오 반복(월 이동 20회, 일정 열고 닫기 20회) → 다시 측정.
  - `Get-Process`의 `WorkingSet64`와 `performance.memory.usedJSHeapSize`를 표로 기록한다.
  - 같은 조작을 반복할 때마다 계속 오르면 누수 후보로 둔다. 한 번 측정한 값만으로 단정하지 않는다.
  - 아무것도 안 할 때 CPU가 0에 가까운지 본다. `activeWindow.ts`가 1초마다 폴링하고, 번들 업데이트가 1시간마다 확인한다(`bundleUpdate.ts`).
- **날짜 변경** `[수동]`
  - 자정을 넘길 때 앱을 재시작하지 않아도 오늘 표시, D-day, 하단 목록이 바뀌는지 확인한다.
  - 시스템 시계를 바꾸는 방법은 쓰지 않는다. 사용자 환경 전체에 영향을 준다.
- **오프라인 복귀** `[수동]`: 네트워크를 끊었다가 다시 연결했을 때 동기화가 재개되는지, 에러 토스트가 쌓이지 않는지.

## 5. 설치·업데이트

패키징 빌드에서만 의미가 있다. dev 빌드에서는 "해당 없음"으로 적는다.

- **셸 업데이트**(`autoUpdate.ts`, electron-updater) `[관측]`: `main.log`에 확인 → 다운로드 → 설치 흐름이 남는지. 업데이트 뒤 `store` 설정(창 위치, 알림)이 유지되는지.
- **번들 업데이트**(`bundleUpdate.ts`) `[관측]`
  - `main.log`에 서명 검증과 교체 기록이 남는지.
  - `%APPDATA%\Mirinae\bundle-update\`에 build 폴더가 계속 쌓이지 않는지.
  - 매니페스트를 받지 못했을 때(오프라인) 내장 번들로 정상 부팅되는지.
- **설치·제거** `[수동]`: 설치 후 첫 실행, 제거 뒤 자동 시작 항목이 남지 않는지.

## 6. 결과 작성 방식

- **저장 위치:** `.claude/qa/common.md`의 "보고" 섹션을 따른다.
- **섹션 순서:** 요약 표 → 방법 → 확인됨 → 🔴 높음 → 🟡 중간 → 🟢 낮음 → 사용자 체크리스트 → 검증하지 못한 항목. 심각도 기준, 제목 형식, 리포트 뼈대는 `common.md`의 "보고" 섹션을 그대로 따른다.
  - **방법:** OS 빌드, 모니터 구성과 배율, dev/패키징, 앱 버전
  - **확인됨:** 항목마다 수단 표시(`[PostMessage]`/`[관측]`)를 붙여 한 줄씩
  - **심각도 섹션:** 각 문제는 기대/실제 → 재현 정보(`qa-functional` 4번과 같은 항목. 환경 조건도 추가: 모니터 구성, 배율, 포커스 상태). 원인 추적은 하지 않는다
  - **사용자 체크리스트:** `[수동]` 항목을 "할 일 → 볼 것" 형식으로
  - **검증하지 못한 항목:** 이유와 함께
- 메모리·CPU 측정값은 표로 남긴다(시점, 조작, WorkingSet, JS heap, CPU).
