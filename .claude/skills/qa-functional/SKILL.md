# 기능 QA — 동작·버그 탐색

목표는 "되는가"보다 **"어디서 깨지는가"**를 찾는 것이다. 버그를 찾으면 코드를 읽어 원인 위치까지 짚는다. 수정은 하지 않는다.
실행 환경, 조작 요령, 안전 수칙은 `qa` 에이전트 문서를 따른다.

## 1. 기본 시나리오 (매번)

모든 데이터 변경은 `[QA]` 일정에만 한다. 각 단계마다 다음 세 가지로 결과를 확인한다.
- 화면
- 토스트
- 새로고침 후 서버 상태

| 기능 | 확인할 것 |
| --- | --- |
| 추가 | 시간 일정, 종일, 반복, 여러 날에 걸친 일정. 저장 후 달력·하단 목록(오늘/다가오는/카테고리)에 반영되는지 |
| 수정 | 제목, 시간(+/− 버튼, 슬라이더), 날짜 범위, 색상. 폼을 다시 열었을 때 값이 유지되는지 |
| 완료 | 완료 표시(취소선) → 실행 취소로 복구. 하단 목록에도 완료 상태가 반영되는지 |
| 이동 | 드래그(CDP라 로직만 검증). 기간이 유지되는지, 다른 주로 넘어갈 때 표시 |
| 삭제 | 삭제 → 실행 취소 토스트 → 토스트가 사라진 뒤 새로고침해도 없는지 |
| 보기 | 월 이동, 캘린더 접기/펼치기, 미니뷰, 표시할 캘린더 토글, 색상 필터, 다크 테마(되돌릴 것) |

## 2. 엣지 케이스

- **입력(`HangulInput`):**
  - 한/영 전환, Backspace로 자모 단위 삭제, Delete, 선택 영역 덮어쓰기, Ctrl+A, 붙여넣기
  - 긴 제목, 빈 제목 저장
- **시간:**
  - 종료가 시작보다 빠른 입력, 자정 넘김, 종일 토글 on/off 시 시간 보존
- **날짜:**
  - 월 경계·주 경계를 넘는 일정, 다음 달로 이어지는 일정의 표시
  - 오늘 기준 D-day 계산
- **연속 조작:**
  - 저장 버튼 연타
  - 실행 취소 토스트가 떠 있는 동안 다른 작업
  - 모달이 열린 채 토스트 클릭
- **표시:**
  - 하루에 일정이 많을 때 "+N개 일정" 처리
  - 툴팁과 드롭다운이 겹치는지
  - 호버 상태가 남는지
- **상태 유지:**
  - 새로고침 후 설정 유지 여부
  - 새로고침 직후 `disable-click` 재적용 여부

## 3. 매번 같이 확인할 것

- **콘솔:**
  - 조작 전후로 `browser_console_messages(level: "warning")`을 확인한다.
  - 새 에러나 경고가 나오면 어떤 조작에서 나왔는지 기록한다.
  - Electron CSP 보안 경고처럼 dev 모드에서만 뜨는 경고는 구분한다.
- **접근성 트리:**
  - `browser_snapshot`에서 이름 없는 `button`, 역할 없는 클릭 요소를 기록한다.
- **플랫폼 제약 위반:**
  - 새로 발견한 UI가 `CLAUDE.md` 제약(휠 스크롤 의존, 드래그 의존, `<img>`, 일반 `<input>`, CSS `:hover`)을 어기면 기록한다.
  - 호버는 `shared/hooks/useHover.ts` 패턴(`data-hoverable`)이 표준이다.

## 4. 원인 추적

버그를 재현하면 다음 순서로 원인을 짚는다.
1. 코드를 Grep/Read로 찾아 `파일:줄`을 적는다.
2. 원인이 `node_modules`(예: `electron-as-wallpaper`)에 있으면 그 위치와, 앱 쪽에서 막을 수 있는 지점을 같이 적는다.
3. 원인을 확인하지 못했으면 "원인 미확인"이라고 쓴다. 추정은 추정이라고 밝힌다.

## 5. 결과 작성 방식

- **저장 위치:** `QA-YYYY-MM-DD.md`(오늘 날짜).
- **섹션 순서:** 방법 → 정상 동작 → 심각 → 버그 → UX → 기타.
  - **방법:** 앱 버전, 범위, 테스트 데이터, CDP 한계
  - **정상 동작:** 확인된 기능을 한 줄씩
  - **심각:** 데이터 손실·유출, 핵심 작업 불가
  - **버그:** 재현 → 기대/실제 → 원인 `파일:줄` → 제안
  - **UX:** 동작은 하지만 혼란을 주는 것. 깊은 평가는 `qa-ux`로 넘긴다.
  - **기타:** 분석, 개발 환경, 코드 컨벤션 위반 등
- **재현 경로:** 다른 사람이 따라 할 수 있게 구체적으로 쓴다(어느 셀, 어떤 키, 어떤 입력값).
- **불확실한 항목:** 재현했지만 원인이 불분명한 것, 한 번만 관찰된 것은 "(미확인)"을 붙인다.
