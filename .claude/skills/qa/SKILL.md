# QA 지휘

메인 대화가 이 절차대로 QA 서브에이전트를 부른다. 서브에이전트는 다른 서브에이전트를 부를 수 없으므로, 순서와 중단 판단은 메인 대화가 한다.
QA 규칙(실행 환경, 안전 수칙, 리포트 경로)은 `.claude/qa/common.md`에 있다. 여기서는 순서와 판단만 다룬다.

## 1. 범위 정하기

| 요청                                       | 실행할 에이전트           |
| ------------------------------------------ | ------------------------- |
| 관점 없음 ("QA 해줘", "전체 QA")           | `qa-functional` → `qa-ux` |
| 기능·버그·회귀                             | `qa-functional`           |
| UX·사용성·첫 사용자                        | `qa-ux`                   |
| 실기·입력 경로·멀티 모니터·메모리·업데이트 | `qa-platform`             |

- `qa-platform`은 대부분 사람이 직접 해야 하는 항목이라, 명시적으로 요청할 때만 넣는다.
- 기능을 먼저 돌린다. 핵심 기능이 깨져 있으면 UX 평가의 의미가 줄어든다.
- 특정 기능만 봐 달라는 요청이면 그 범위를 에이전트 프롬프트에 넣는다.

## 2. 실행 전 확인

- 앱이 떠 있는지 `curl -s http://localhost:9222/json/list`로 확인한다.
  - 없으면 메인 대화가 `npx electron-vite dev --remoteDebuggingPort 9222`를 백그라운드로 띄우고 포트가 열릴 때까지 기다린다. 에이전트마다 앱을 따로 띄우지 않게 하기 위해서다.
- 사용자에게 다른 앱에 포커스를 둔 채로 진행해도 되는지는 묻지 않는다. 에이전트가 `disable-click` 제거 스크립트로 처리한다.

## 3. 순서대로 실행

- 에이전트는 **한 번에 하나만** 실행한다. 같은 앱, 같은 CDP 세션, 같은 계정을 쓰므로 동시에 돌리면 클릭과 `[QA]` 일정이 섞인다.
- 서브에이전트는 백그라운드로 돈다. **완료 알림을 받은 뒤에** 다음 에이전트를 실행한다. 알림 전에 결과를 짐작해 말하지 않는다.
- 프롬프트에는 범위와 오늘 날짜만 넣는다. 앱 사용법이나 화면 구성을 설명하지 않는다. 특히 `qa-ux`에는 기능 QA 결과를 전달하지 않는다. 첫 사용자 관점이 깨진다.

### 중간 판단

`qa-functional`이 끝나면 기본적으로 **묻지 않고 바로** `qa-ux`를 실행한다. 아래처럼 다음 에이전트가 앱을 쓸 수 없는 경우에만 멈추고 사용자에게 묻는다.

- 앱 멈춤으로 중단됐다고 보고됨 → 앱을 다시 띄울지 묻는다.
- 로그인이 풀렸거나, 일정을 하나도 만들 수 없음.
- `[QA]` 일정이 남아 있다고 보고됨 → 먼저 `qa-functional`을 "남은 `[QA]` 일정 정리만" 하는 프롬프트로 한 번 더 부른다. 그래도 남으면 멈춘다. 남은 일정은 다음 에이전트의 화면을 오염시킨다.

그 외의 심각 항목(데이터 손실, 일부 기능 불가 등)은 멈추지 않는다. 메모해 두고 4번 결과 정리 때 맨 위에 보고한다.

## 4. 결과 정리

모든 에이전트가 끝나면 사용자에게 아래를 한 번에 보고한다.

- **리포트 경로:** 에이전트별 파일 링크.
- **심각·버그:** 리포트에서 뽑아 심각도순으로 한 줄씩. 여러 리포트에 같은 문제가 있으면 묶는다.
- **UX 상위 문제:** `qa-ux`의 "우선 개선할 5가지".
- **사용자 체크리스트:** `qa-platform`을 돌렸다면 `[수동]` 항목.
- **정리 상태:** 테스트 데이터 정리 여부, 되돌린 설정, 앱이 아직 떠 있는지.
- **검증하지 못한 항목.**

## 5. 다음 단계 제안

- 버그가 있으면, 버그별로 `diagnosing-bugs`로 원인을 추적할지 묻는다. 버그마다 새로 시작하는 게 context에 유리하다.
- 바로 고치지 않는다. 사용자가 고칠 대상을 고른 뒤에 진행한다.
