# QA 공통 규칙

`qa-functional`, `qa-ux`, `qa-platform` 에이전트가 함께 따르는 실행 환경, 안전 수칙, 보고 규칙이다.

- **코드는 읽지도 수정하지도 않는다.** 원인 추적은 리포트를 받은 쪽에서 한다.
- **세 에이전트는 동시에 돌리지 않는다.** 같은 앱, 같은 CDP 세션, 같은 계정을 쓴다.

## 실행 환경

- 앱: 저장소 루트에서 `npx electron-vite dev --remoteDebuggingPort 9222`로 띄운 dev 빌드.
  - 먼저 `curl -s http://localhost:9222/json/list`로 떠 있는지 확인한다.
  - 없으면 백그라운드로 실행한 뒤 포트가 열릴 때까지 기다린다.
- 조작 도구: Playwright MCP(`mcp__playwright__*`, CDP 9222에 붙음).
  - 스크린샷은 `.playwright-mcp/`에만 저장할 수 있다.
- 계정: 이미 로그인된 사용자 본인의 Google 계정이다. **실제 데이터다.**

### 테스트 환경의 한계와 우회 방법

- **클릭 차단:** 다른 앱(터미널 등)에 포커스가 있으면 `html.disable-click`이 걸려 클릭이 막힌다.
  - 시작할 때 아래 코드를 한 번 실행해 이 클래스를 계속 제거한다. 새로고침하면 다시 실행해야 한다.
  - 전역 CSS로 `pointer-events`를 덮어쓰지 말 것. 일부러 넣은 `pointer-events-none`까지 깨진다.
  ```js
  () => {
    if (window.__qaStrip) return;
    window.__qaStrip = true;
    const h = document.documentElement;
    const strip = () => {
      if (h.classList.contains('disable-click')) h.classList.remove('disable-click');
    };
    strip();
    new MutationObserver(strip).observe(h, { attributes: true, attributeFilter: ['class'] });
  };
  ```
- **CDP 입력의 한계:** CDP 입력은 Windows의 실제 입력 전달 경로(`forwardMouseInput`)를 거치지 않는다.
  - 드래그·클릭 결과는 "로직 검증"으로만 취급하고, 실제 환경에서의 체감은 "추가 검증 필요"로 분리한다.
  - 휠 스크롤은 실제 앱에서 전달되지 않으므로 평가하지 않는다.
- **다른 앱의 키 유입:** OS 키보드 입력이 포커스와 상관없이 앱으로 전달된다. 그래서 입력칸에 내가 치지 않은 문자가 섞일 수 있다.
  - 저장하기 전에 `browser_evaluate`로 입력값을 꼭 확인한다.
- **호버 섞임:** 사용자의 마우스가 앱 위에 있으면 호버 상태(셀 하이라이트, 툴팁)가 스크린샷에 섞인다. 내 조작의 결과인지 구분한다.
- **투명 창:** 창이 투명해서 빈 영역은 스크린샷에서 흰색으로 보인다.
- **버튼 지정:** 아이콘 버튼은 접근성 이름이 없는 경우가 많다.
  - 이름 없이 ref로 지정하면 Playwright가 `getByRole('button').nth(n)`로 풀어서 다른 버튼을 누를 수 있다.
  - 데이터를 바꾸는 버튼을 누른 뒤에는 결과 토스트나 화면으로 무엇이 눌렸는지 확인한다.
- **앱 멈춤:** Playwright 호출이 응답하지 않으면 다시 호출하며 기다리지 않는다. 대신 다음을 확인하고, 직전 조작을 재현 경로로 남긴 채 QA를 중단한다.
  - 렌더러 CPU 사용량(`Get-Process electron`)
  - dev 서버 로그
  - 앱 재시작은 메인 대화에 요청한다(프로세스 강제 종료 권한 없음).

## 안전 수칙

- **기존 데이터:** 기존 사용자 일정은 절대 수정하거나 삭제하지 않는다. 보기만 한다.
- **테스트 일정:** 제목에 `[QA]`를 붙여 만들고, 수정·이동·완료·삭제는 이 일정에만 한다.
- **하지 않는 작업:** 아래는 수행하지 말고, 필요하면 메인 대화에 확인을 요청한다.
  - 로그아웃, 앱 종료, 계정 연결 해제, 초대 전송, 외부 알림 발송
- **사용자 설정:** 테마, 투명도, 화면 구성, 색상 필터, 알림 등을 바꿔 보았다면 반드시 원래 값으로 되돌린다.
- **마무리 확인:** 끝나면 새로고침(헤더 새로고침 버튼) 후 `[data-event]`에 `[QA]` 일정이 남아 있지 않은지 `browser_evaluate`로 확인한다.
- **산출물 정리:** 리포트에 근거로 인용한 스크린샷을 빼고, `.playwright-mcp/`의 산출물은 지운다. 이 폴더는 gitignore 대상이 아니다.
- **실행 상태 보고:** 앱을 직접 띄웠다면 계속 실행 중인지 보고한다.

## 보고

- 리포트는 `docs/`에 에이전트별로 따로 저장한다. 파일명의 날짜는 오늘 날짜다.

  | 에이전트        | 파일                             |
  | --------------- | -------------------------------- |
  | `qa-functional` | `docs/QA-YYYY-MM-DD.md`          |
  | `qa-ux`         | `docs/UX-QA-YYYY-MM-DD.md`       |
  | `qa-platform`   | `docs/PLATFORM-QA-YYYY-MM-DD.md` |
  - 같은 날짜 파일이 이미 있으면 덮어쓰지 말고 뒤에 `-2`, `-3`을 붙인다.

- **심각도별 정리:** 문제는 종류(버그/UX 등)가 아니라 심각도로 크게 나눈다. 리포트 최상위 섹션으로 `## 🔴 높음` → `## 🟡 중간` → `## 🟢 낮음`을 두고, 해당 문제가 없는 섹션은 "없음"이라고 한 줄 쓴다.

  | 표시 | 심각도 | 기준 |
  | --- | --- | --- |
  | 🔴 | 높음 | 데이터 손실·유출, 핵심 작업 불가, 사용자가 실패를 성공으로 믿게 됨 |
  | 🟡 | 중간 | 작업은 되지만 우회가 필요하거나 반복적으로 혼란을 줌 |
  | 🟢 | 낮음 | 가독성·일관성·편의 문제, 콘솔 경고 |

- **확인을 못 한 문제**도 세 단계 중 하나로 매기고, 제목 끝에 `(추가 검증 필요)`를 붙인다.
- **문제 제목 형식:** `### 🔴 ID. [종류] 제목`. 종류는 `[버그]`, `[UX]`, `[환경]` 중 하나다. ID는 리포트 안에서 고유하면 된다(예: `F1`, `U1`, `P1`).
- **요약 표:** 리포트 제목 바로 아래에 모든 문제를 심각도순으로 모은 표를 둔다. 열은 `심각도 | ID | 종류 | 영역 | 내용(한 줄)`. 상세는 그 아래 심각도 섹션에 쓴다.
- **지난 리포트에서 이어진 문제**는 제목 끝에 `(지난 리포트부터)`를 붙인다. 심각도는 지난번 값을 그대로 쓰지 말고 이번 기준으로 다시 매긴다.
- **문제는 하나씩 `###` 제목으로 쓴다.** 작은 UX 관찰도 문단이나 글머리표 목록에 몰아 쓰지 않는다. 상세 내용은 제목 아래 글머리표로 쓴다.
- **리포트 뼈대:** 에이전트마다 앞뒤 섹션(방법, 확인됨, 총평 등)은 다르지만, 문제 부분은 항상 아래 모양이다.

  ```md
  # 기능 QA 리포트 — 2026-10-19

  ## 요약

  | 심각도 | ID | 종류 | 영역 | 내용 |
  | --- | --- | --- | --- | --- |
  | 🔴 | F1 | 버그 | 일정 폼 | 종료<시작이면 저장 안 되는데 성공 토스트 |
  | 🟡 | F2 | UX | 삭제 메뉴 | 아래 일정의 ✓/✕ 위에 겹쳐 뜸 |
  | 🟢 | F3 | 버그 | 콘솔 | `value` prop 에러 (지난 리포트부터) |

  ## 방법
  (에이전트별 섹션)

  ## 🔴 높음

  ### 🔴 F1. [버그] 같은 날 종료가 시작보다 빠르면 저장 안 되는데 성공 토스트가 뜸

  - **기대:** …
  - **실제:** …
  - **재현 경로:** …
  - **재현율:** 2/2

  ## 🟡 중간

  ### 🟡 F2. [UX] 삭제 메뉴가 아래 일정의 ✓/✕ 위에 겹쳐 뜸

  - …

  ## 🟢 낮음

  ### 🟢 F3. [버그] 폼을 열 때마다 `value` prop 콘솔 에러 (지난 리포트부터)

  - …

  ## 검증하지 못한 항목
  (에이전트별 섹션)
  ```

- 메인 대화에는 핵심 결과 요약만 반환한다.
- 원인 추적은 메인 대화가 리포트를 받은 뒤 버그별로 따로 한다(`diagnosing-bugs` 스킬). 그래서 리포트의 재현 정보만 보고 따라 할 수 있어야 한다.
- 요약에는 다음을 반드시 넣는다.
  - 만든 테스트 데이터와 정리 여부
  - 바꿨다가 되돌린 설정
  - 검증하지 못한 항목
